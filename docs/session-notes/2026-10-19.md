# Session notes, Oct 19 (night session, T0 calibration, E1b, E0b)

## Ideas (Nick)
- **Separate, higher-quality camera for calibration only.** A mobile
  high-quality camera (e.g. a phone) could be used during setup/calibration
  for sharper corner and robot-point clicks, while production runs keep the
  fixed overhead camera. Needs: a way to carry the calibration from the mobile
  camera's view into the fixed camera's (shared floor points seen by both),
  and a test of whether it beats the fixed camera's own calibration
  (tonight: 14 points, RMS 0.52 cm, leave-one-out 0.82 cm).

## Findings
- **Look-around sees the plywood as a wall.** Left's calibration (C704-2):
  room 8.3 to 10.9 cm in all 8 directions, nearest 15.8 cm from the turning
  centre. The front sensor's view reaches the floor about 4 in ahead; the
  look-around counts it as an obstacle, so it never rolls ("limited, no
  room"). Fix in firmware: ignore returns at about the same distance in every
  direction (the floor), or learn the floor distance per zone. Until then
  every calibration run is limited.
- **E1b: zero runs.** Right fell from 26% to 8% while idle; at its turn it
  showed two blinking red lights and could not keep WiFi. Next time start the
  low-battery block as soon as Right is switched on.
- **E0b method change.** Runs 2 onward: the robot is lined up on the run 1
  start ticks (the original L marks) each run; START marks = those ticks.
  Nick measures END marks as changes from the ticks (to 1/32 in).
  Run 2's start was deferred (after a bump the robot was re-placed on the
  ticks).
- **Camera calibration (T0cal, 20261019-022244):** 4 corners + 10 robot
  points; RMS 0.52 cm, max 0.89 cm, leave-one-out 0.82 cm. Point 5 was a
  duplicate corner click, unticked.
- **Calibration page:** "Save calibration" shows the same text on a re-save,
  so it looks like nothing happened. Add the save time.
- Center's WiFi was weak (-82 dBm) at preflight.
- **Left's start roll curves (Nick, by eye, E0b run 6).** The left wheel
  pulls harder, so the roll bends a little right on the way out and curves
  back to the start on the return. Matters for E0b: the camera reads heading
  from the roll's direction, so a curved roll gives a heading biased toward
  the bend. heading_check.py's camera-minus-tape difference should show it as
  a steady offset (not just spread) for Left; compare with Center. Also a
  sign the two wheels differ in size or motor strength: the wheel-scale
  calibration and the wheel-only end error in E1 should pick it up.
- E0b runs 3 to 6 (5 cm roll): each ended 1/32 to 1/16 in forward (+x) and
  the same to the right (-y), almost no turn.
