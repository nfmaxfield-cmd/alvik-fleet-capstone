# Session plan, Thursday 2026-10-29 (daytime): the board in bright light, with today's camera fixes

**Premise.** On 28 Oct at 16:29, in late-afternoon daylight, the overhead camera saw the robots' bodies in only 3 of
29 checks, and every robot was set aside within 12 minutes. The cause (docs/build-reports/e02-oct28-overhead-contrast.md):
in daylight the robots' tops stood only 12-28 grey levels from the board (24-37 under the lamp at night), and where a
robot had stood when tracking began the tracker saw only pieces of it. That made the first 10 cm crawl read 12-18 cm
and the turn checks misread. The tracker now sees the whole robot there. Replayed on 28 Oct's own pictures, the
overhead now sees the body 97 % of the time (it was 78 %). A lighting check now runs before anything moves. Today
tests that on the real board, in daylight, with the board as it is now (122 x 122 plywood, no boards).

**Update after the 19:17 keep-going loop (28 Oct, build-reports/e02-oct28-keep-going-run.md).** That loop ended after
27 minutes with all three robots set aside, none of it the robots' fault. Today's code also has those fixes. The loop
now drives a robot that is too near an edge back to open space instead of setting it aside. It re-measures a heading
after any drive that did not finish. It asks a robot whether a leg has ended when the "done" message is lost. And it
no longer calls a robot "lost" while both cameras see it. Stage 3 lists the new lines you may see.

**When:** daytime, ideally the same light as yesterday's 16:29 (sun from the window). If it gets dark before you
start, switch off the lamp directly above the table and use the ceiling light: under that lamp at night the overhead
read "washed out" (robots 16 grey levels from the board; it needs 18). **Time:** about 1 h 15 min.

## Stage 3. The DOE loop, 1 hour (60 min, you can walk away)

1. Pi window:

```
./run-fleet-pi.sh doe 1
```

You should see `DOE loop started in tmux session 'doe' (time cap 1 h ...)`. You can close the window: it keeps going.

2. To watch it (any time). Pi window:

```
tmux capture-pane -p -t doe | tail -40
```

In the first minute you should see:
- `Lighting check (before anything moves):` with one line per camera (as in Stage 2);
- `Left: body seen by both cameras` (and the same for Right and Center): the pass mark is 2 of 3 or better;
- `L0 PASS`.

Lines that are now normal and not a failure:
- `crawling again to re-check`: the first crawl read off; the second one counts.
- `[held] ...: held, not set aside; checked again next time`: one camera's evidence; it stays in.
- `... cm from the x = ... edge (a turn check or a drive needs 25 cm ...): driving it to open space at (..) first`,
  then `[room made]`: a robot that drifted near an edge or another robot is driven back in, slowly, by the planner.
- `[heading unknown] ...: a camera-watched heading crawl comes first next time`: a drive did not finish, so its
  heading is measured again before the next move.
- `not seen standing still: holding (nothing moves) and looking again`, then `found again`: the cameras' spots
  wobbled; it waits and looks again instead of calling the robot lost.

Lines to tell me about straight away (note the time): `[parked]` for any reason, and any robot that stops less than
15 cm from an edge.
